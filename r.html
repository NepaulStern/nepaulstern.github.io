The Nepaul-Stern Model in R

The Nepaul-Stern Model of Attitude Stability and Constraint is for panel surveys that ask the same people the same attitude questions more than once. The answers are on Likert scales (strongly agree to strongly disagree, liberal–conservative, party identification). Several related attitudes are measured together. Waves may be unevenly spaced, and a person may miss a wave or leave an item blank. Covariates such as age or education can be included.

The questions are about stability (how firmly an attitude persists), constraint (how much one attitude moves with another), how much of the variation comes from lasting individual differences, short-run change, and measurement noise, how a shock to one attitude spreads across later waves, and how covariates relate to the attitudes. Nepaul and Stern (2026) discuss the General Social Survey results. This page is about estimating the model.

Install

You need R 4.0 or newer. On Windows and macOS, CRAN provides a ready-made install, so you do not need a compiler.

Linux, and installing without a compiler

On Linux, install.packages("attitudedyn") builds the package on your computer, which needs a C++17 compiler. If you would rather not compile, the Posit Public Package Manager and r2u provide ready-made Linux installs. On the Posit site, choose your distribution and use the repository address it shows. r2u does the same for Ubuntu.

A survey of your own

Put the survey in a data frame with one row per person per wave. id identifies the person and wave identifies the interview. Code each Likert item as the integers 1, 2, 3, and so on, with no skipped code. Leave a skipped item as missing. If someone misses a wave between their first and last interview, keep a row for that wave so the attitude can be carried across it.

For a new sample, use 50 draws. The default is 10, which is what the General Social Survey replication uses. n_threads is how many processors to use. Changing it changes the waiting time. The estimates stay the same. seed = 1 is the default, and it leaves R’s usual random numbers alone.

R adds an intercept for you. Write the formula that way when every row is a real interview. The General Social Survey example below already has an intercept column in the data, and that column is 0 on a wave that was only inserted to fill a gap, so its formula is written 0 + `(Intercept)`.

The General Social Survey example

The numbers below are the printed output from the General Social Survey application in Nepaul and Stern (2026): six Likert items, on the 2006–2020 panels. The items are ideological identification (7 categories), military spending (3), welfare spending (3), the number of immigrants (5), party identification (7), and environmental spending (3). The replication data are on the Harvard Dataverse. The survey file the example reads is gss2.prn. Read it into a data frame named panel, one row per person per wave, with the columns below. The Python package can build that data frame with read_gss().

ColumnWhat it is
id, wavePerson and wave. Waves in this file are 1 through 8. No missing values.
weightA survey weight, zero or positive, and the same on every row for that person.
(Intercept), age, hs, college, adv, female, white, black, inc_mid, inc_highCovariates. The intercept is 1 on a wave that was in the file and 0 on a gap row.
ideology, military, welfare, immigrants, party, environmentThe Likert items, coded from 1.

Of the 11,282 people in the file, 11,252 have a positive weight and enter the likelihood. Everyone uses the same wave dates, c(2, 3, 4, 5, 6, 7, 8, 10): wave 1 is date 2, and wave 8 is date 10. The gaps are seven steps of 1 and then a step of 2 between the last two waves. Pass that shared grid for this application.

estimates holds the 164 replication starting values, in the order coef() uses. maxit = 0 evaluates that vector and returns. draws = 10 and seed = 1 are the replication defaults: ten simulated paths, each paired with its mirror image (antithetic draws). On 4 threads that evaluation takes a few seconds.

A full search from those starting values took 202.6 seconds on 4 threads. It stopped with convergence code 0 at log-likelihood -111545.0088160454. The tables on this page are the evaluation of the starting values. That log-likelihood is -111570.9702226093, which summary() prints as -111571.

Then read the fit. The small draw count in predict() is only the setting that produced the printed excerpt. In your own work, leave n_draws at its default, which is at least 20.

Summary

summary(fit) opens with the sample size and the log-likelihood, then prints every free coefficient. There are 164 of them. glance(fit) is one row of fit statistics. tidy(fit) is the coefficient table as a data frame. These are the opening lines, the one-row summary, and the first rows of tidy(fit) (the ideology wave effects).

Persistence and impulse responses

persistence_matrix() is on a scale from −1 to 1. The row is the attitude that receives the past. The column is the attitude that is lagged. summary() prints that matrix rounded to three decimals. The function itself prints more digits.

impulse_response() follows a one-unit shock. Horizon 0 is the shock itself. Later rows are the response after that many steps. For this fit the spectral radius is 0.636678. The figure is the same grid: rows respond, columns are the shock. Nepaul and Stern (2026) discuss what the paths mean.

Variance decomposition

variance_decomposition() reports four pieces for each latent attitude. covariate is the variance of the wave effect plus the covariates. wave_effect is the wave effect on its own. factor is the sum of squared loadings, the part that stays with the person across waves. shock is the average short-run contribution built from the persistence coefficients. total adds the four.

Predicted categories and a new panel

predict(..., type = "class") is the Likert category with the highest probability. type = "prob" is the probability of each category. The excerpt below is ideology. The row numbers skip, because they are positions in the person-by-wave array and waves outside a person’s window are still in that array.

simulate() draws a new panel from the fitted coefficients, with 11,252 people and 8 waves (90,016 rows). The intercept column is ones. The other covariates are standard normal. The seed used for the printed rows is 2.

The corner of the stored covariance matrix

summary() uses the covariance stored with the fit. Here that is opg_centered. This is the corner of that matrix.

How it works, briefly

The arithmetic is done by a C++17 program that has no libraries of its own. The R package calls that program.

The likelihood is simulated, by the Geweke–Hajivassiliou–Keane (GHK) method. The slope of the likelihood is analytic, and the search uses BFGS.

The random draws use Philox. Each draw is tied to the seed, the person, and the draw number, so the same data and seed give the same answer with any number of threads, and on Windows, macOS, and Linux.

The loop over people can use several threads. Standard errors can be the outer product of the person-level scores (the default, opg_centered, or the uncentred opg), the curvature of the likelihood (hessian), or the sandwich combination of those two.

For the substantive reading of a set of estimates, including the General Social Survey application, see Nepaul and Stern (2026).
